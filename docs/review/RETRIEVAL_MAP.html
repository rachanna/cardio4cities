Four corrections to the brief's assumptions

  1. Question answering is not a LangGraph graph. It is plain async code, answer_question pipeline.py:76, with the four routes run by asyncio.gather :91-96. LangGraph runs only the research workflow graph.py:79-154.
  2. Graphiti holds no episodes and makes no model calls. Nodes and edges are saved directly with episodes=[] graphiti.py:179; Graphiti's model client refuses every call :69-79.
  3. No path ingests a single document. Pages enter only through a research run (search, crawl gate, fetch). A file-ingest script would bypass the crawl gate, which the project's rules forbid.
  4. No instance is deployed. config/deployed.yaml exists; tracing there is [events] and nothing else deployed.yaml:42.

Idempotent

Every ID is deterministic (uuid5 or stable_id), upserts overwrite, graph_link is checked before a write graph_writes.py:119, and events are keyed by their content events.py:17-22.

Not transactional across stores

Postgres commits first. Qdrant and graph failures are logged and swallowed claim_index.py:81-82, graph_writes.py:134-136. The graph write is retried once at brief_ready; the claim index is not retried.

Write sites: fetch_parse.py:128 (source), :138 (snapshot), :146 (chunks); claim_index.py:49-57 (status); finish.py:22-37 (write node).

5Fusion and prompt assembly

  • Reciprocal rank fusion on ranks only: score = Σ 1 / (60 + rank), ties broken by the trust ranking key fuse.py:14-38. Routes return bare claim IDs, so Qdrant's cosine scores are dropped inside R3 semantic.py:40, and no score threshold exists.
  • No reranker. Graphiti's is disabled; nothing reranks after fusion.
  • Anchors: each asked slot's best claim is injected if no route found it, or its gap record is attached fuse.py:48-72.
  • Bundle: asked slot order, anchored first, then score; at most 8 facts and 2 per slot; contested pairs kept whole; mentions only for open questions with fewer than 3 facts bundle.py:18-63.
  • Prompt: fact lines pipeline.py:214-233, mentions and gap lines, built by context.build_user_message; one repair on invalid output; fetched text escaped by escape_untrusted llm.py:24-61.

6Two fact-checking stages

Model Checker, research

verify.py:34-60

In: one claim, its labels, and the passage code located in source.parsed_text.

Out: a verdict row (supported, refuted, insufficient) that sets claim.status. Only a supported verdict can make a fact.

Code Post-check, answering

postcheck.py:1-5

In: the answerer's sentences and the bundle's evidence, all from Postgres.

Out: each sentence kept, repaired from stored values, or removed and replaced by an abstention; recorded in trace.post_check.

8Cross-store consistency risks

Reported only. Nothing here is fixed in this work.

#SeverityRiskWhereEffect today
R1MediumDesign drift. The architecture says graph reads use Graphiti's hybrid search; R4 never passes query text, so edge and name embeddings are written and never queriedgraph.py:30 vs graphiti.py:226Graph retrieval is type-filtered Cypher only
R2Medium-highGraph partitions are per city, not per run. Older runs' edges stay in the group. R4's limit of 50, newest valid_at first, can let old-run edges crowd out the latest run's before re-validation drops them as other_rungraphiti.py:264-275A recall loss that grows with every run of a city
R3MediumClaim index has no retry. A failed Qdrant upsert or delete is only loggedclaim_index.py:81-82Missing points cost recall (R1, R2 and anchors cover); stale points are caught by re-validation

9Decisions before Phase 1

  1. Fetched text in traces. CLAUDE.md says fetched text is untrusted and never logged; a full trace needs chunk text and prompts. Either (a) local, git-ignored trace files with tracing off in every deployed profile, recorded as a BD- row, or (b) fetched text kept only as length, hash and the first 80 characters.
  2. Ingestion trace. Trace one source of a real run by source_id (source row, chunks, claims, claim-index points, edges and graph_link) instead of ingesting a local file past the crawl gate.
  3. "Identical answers" with tracing off. The answerer runs with effort and no seed, so live answers vary. Compare the deterministic parts of the trace (routes, fused list, bundle) across live runs, and use the scripted-model tests for exact equality.
  4. Data for the demo question. The stores must be running (uv run poe up) to choose a question the loaded data can answer.
